At it's core, the part of the file system that we interact with can be viewed as a graph - more specifically, a directed acyclic graph (DAG). We know about DAGs from CS 2110 and CS 2800, so let's examine the pieces that make up this structure!

### Nodes

There are two main kinds of nodes that we interact with:

1. Files: Documents, programs, images, source code, or any other data stored on your computer (ex. `document.pdf`, `main.ml`). A dot separates the file name from its format type so your computer knows which program to open it with. 

Some special files on your computer contain the file name *after* the dot with no file type (ex. `.gitignore`, `.bashrc`). These are called [dotfiles](https://wiki.archlinux.org/title/Dotfiles), and we'll come back to them later.

2. Directories: Folders that can hold files and/or other directories. Since our filesystem is a directed acyclic graph, we cannot have cycles, so a directory cannot contain itself.

One directory is specially designated as the root directory, written as `/`. Every file and directory in the file system can be reached by starting from this root and traversing across the edges of the file system, which we explain below.

### Edges

A directory contains named references to its contents. Therefore, an edge can connect: a directory to one of its subdirectories or a directory to one of its files.

For example, the path

`/home/project/main.ml`

describes a sequence of traversals:

`/` → `home` →  `project` → `main.ml`

where `main.ml` is a file in the `project` directory, which is a subdictory of the `path` directory, which is a subdirectory of the `home` directory, which is a subdirectory of the root `/` directory. Whew! Each slash represents an edge, but this is nto to be comfused with the special `/` node that is the root!
