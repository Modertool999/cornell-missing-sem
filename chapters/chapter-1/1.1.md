# 1.1 Navigating the File System

Let’s make our graph model of the file system more concrete by learning how to move around it (i.e., or, how to traverse the DAG).

We will do this using our computer’s **terminal**. The terminal provides a text-based way to interact with our computer. We can use it to navigate the file system, create and modify files, download software, run programs, and perform many other useful tasks.

Okay, let’s start by opening the terminal (how to do this will vary on your machine, but often there is an app installed called Terminal).

When you open a new terminal window, you are automatically “placed at" some node in the file system. The directory you are currently "at" is called your **current working directory**.

By default, this will usually be your **home directory**, which is the directory associated with your user account. Its path commonly looks like:

```text
/home/username
```

on Linux, or:

```text
/Users/username
```

on macOS.

On Windows, the corresponding path usually looks like:

```text
C:\Users\username
```

These paths look different because the operating systems organize their file systems differently. macOS and Linux use Unix-style paths, while Windows uses its own path format. For simplicity, we will primarily use Unix-style paths throughout this tutorial.

The important pattern to notice regardless of your operating system is that the root directory `/` contains some directory, such as `Users` or `home`, which then contains a separate home directory for each user.

For example, my home directory on macOS is:

```text
/Users/modigr
```

We can visualize this path as:

```text
/ -> Users -> modigr
```

## Finding Your Current Location with `pwd`

Let’s see this in action!

Open your terminal, type the following command, and press Enter:

```bash
pwd
```

`pwd` stands for **print working directory**. It prints the absolute (i.e., rooted from `/`) path of the directory you are currently inside.

If you have not changed your terminal’s default settings, you should see the path to your home directory. On my Mac, I see:

```text
/Users/modigr
```

In terms of our graph model, the terminal is telling us which node we are currently visiting, that being the `modigr` directory.

The terminal does not display the entire file-system graph at once. Instead, it keeps track of our current location and lets us move to reachable nodes.

## Viewing a Directory’s Contents with `ls`

Now that we know where we are, we can inspect the files and directories contained inside our current working directory.

Type:

```bash
ls
```

`ls` stands for **list**. It lists the contents of the current directory.

For example, you might see:

```text
Desktop
Documents
Downloads
Pictures
Projects
```

This tells us that our current directory contains entries pointing to each of these subdirectories.


In graph terminology, `ls` shows us all of the nodes that can be reached by following an outgoing edge from our current directory.

You can display more information about each item using:

```bash
ls -l
```

The `-l` option uses the **long listing format**, which includes information such as file permissions, ownership, size, and modification time (the full `inode` that we talked about before! To see each `inode`'s uniqe identifier too, we can do `ls -li`).

You can also include hidden files and directories using:

```bash
ls -a
```

On Unix-style systems, names beginning with a dot are normally hidden from a basic `ls` command (example: dotfiles!)

Running `ls -a` on my home directory reveals a *lot* of hidden files and folders, such as `.docker`, `.julia`, and `.rustup`. A lot fo software out there will automatically create a dotfile in your home directory, contianing user preferences and shortcut settings that you can fiddle with!

## Moving Between Directories with `cd`

To move from one directory to another, we use the `cd` command.

`cd` stands for **change directory**.

Suppose your home directory contains a directory named `Documents`. You can move into it by running:

```bash
cd Documents
```

Your (well, actually my) current working directory is now:

```text
/Users/modigr/Documents
```

You can confirm this by running `pwd` again:

```bash
pwd
```

```text
/Users/modigr/Documents
```

Conceptually, we followed an edge from the `modigr` directory to the `Documents` directory.


There are two main kinds of paths:

1. **Absolute paths**
2. **Relative paths**

## Absolute Paths

An **absolute path** describes a location beginning at the root directory `/`.

For example:

```text
/Users/modigr/Documents/project
```

means:

1. Begin at the root directory `/`.
2. Enter `Users`.
3. Enter `modigr`.
4. Enter `Documents`.
5. Enter `project`.

Because an absolute path always begins at the root, it identifies the same location regardless of your current working directory.

For example, you can run:

```bash
cd /Users/modigr/Documents/project
```

from anywhere in the file system, and you will be taken to that exact directory.

The symbol `/` therefore has two closely related uses:

* By itself, `/` refers to the root directory.
* Inside a path, `/` separates consecutive file and directory names.

## Relative Paths

A **relative path** describes a location beginning at your current working directory rather than at the root.

Suppose your current working directory is:

```text
/Users/modigr/Documents
```

and it contains:

```text
Documents/
├── notes.txt
└── project/
    ├── README.md
    └── main.py
```

You can move into `project` using:

```bash
cd project
```

Because `project` does not begin with `/`, the computer interprets it relative to the current working directory.

The relative path:

```text
project
```

therefore refers to the absolute path:

```text
/Users/modigr/Documents/project
```

Similarly, the relative path:

```text
project/main.py
```

refers to:

```text
/Users/modigr/Documents/project/main.py
```

A relative path only makes sense when combined with a current working directory.

Conceptually:

```text
current working directory + relative path = absolute location
```

For example:

```text
/Users/modigr/Documents + project/main.py
```

produces:

```text
/Users/modigr/Documents/project/main.py
```

## The Current Directory: `.`

A single period:

```text
.
```

refers to the current working directory.

For example:

```bash
cd .
```

means “change into the directory I am already inside,” so it does not move you anywhere.

The symbol is more useful as part of a longer path. For example:

```text
./main.py
```

means “the file named `main.py` inside the current directory.”

Similarly:

```text
./project/main.py
```

means:

1. Begin in the current directory.
2. Enter `project`.
3. Find `main.py`.

The paths:

```text
project/main.py
```

and:

```text
./project/main.py
```

usually refer to the same file. The explicit `./` simply emphasizes that the path begins in the current directory.

You will also often see `./` when running a program stored in the current directory:

```bash
./my-program
```

## The Parent Directory: `..`

Two periods:

```text
..
```

refer to the **parent directory** of the current working directory.

Suppose we are currently inside:

```text
/Users/modigr/Documents/project
```

Running:

```bash
cd ..
```

moves us one level upward:

```bash
pwd
```

```text
/Users/modigr/Documents
```

Graphically:

```text
Documents/
└── project/
```

The parent of `project` is `Documents`, so `..` refers to `Documents`.

We can also use `..` as part of a longer path.

Suppose the file system contains:

```text
Documents/
├── notes.txt
└── project/
    └── main.py
```

If we are currently inside `project`, then:

```text
../notes.txt
```

means:

1. Move to the parent directory, `Documents`.
2. Find the file named `notes.txt`.

You can move upward more than once by combining multiple `..` components:

```bash
cd ../..
```

Starting from:

```text
/Users/modigr/Documents/project
```

the first `..` moves us to:

```text
/Users/modigr/Documents
```

and the second moves us to:

```text
/Users/modigr
```

## The Home Directory: `~`

The symbol:

```text
~
```

is shorthand for your home directory.

On my computer:

```text
~
```

expands to:

```text
/Users/modigr
```

Therefore, running:

```bash
cd ~
```

takes me to my home directory.

You can also use `~` at the beginning of a longer path:

```bash
cd ~/Documents/project
```

For me, this is equivalent to:

```bash
cd /Users/modigr/Documents/project
```

Running `cd` without providing a path also normally returns you to your home directory:

```bash
cd
```

It is important not to confuse `~` with `/`:

```text
/    the root directory of the entire file system
~    your personal home directory
```

For example:

```bash
cd /
```

moves to the root directory, while:

```bash
cd ~
```

moves to your home directory.

Also, `~` is not literally the name of a directory. It is special notation interpreted by your shell, which replaces it with the path to your home directory.

## Putting Everything Together

Suppose the file system contains:

```text
/
└── Users/
    └── modigr/
        ├── Downloads/
        └── Documents/
            ├── notes.txt
            └── project/
                ├── README.md
                └── main.py
```

Suppose our current working directory is:

```text
/Users/modigr/Documents/project
```

Then the following paths refer to:

```text
.                 /Users/modigr/Documents/project
..                /Users/modigr/Documents
../notes.txt      /Users/modigr/Documents/notes.txt
./main.py         /Users/modigr/Documents/project/main.py
~/Downloads       /Users/modigr/Downloads
/Users/modigr     the home directory, written as an absolute path
/                 the root directory
```

Try navigating around your own computer using:

```bash
pwd
ls
cd Documents
pwd
ls
cd ..
pwd
cd ~
pwd
cd /
pwd
```

Looking around with `pwd`, `ls`, and `cd` is generally safe, but you should avoid modifying or deleting unfamiliar system files.

The key ideas to remember are:

* `pwd` tells you where you are.
* `ls` tells you what is inside the current directory.
* `cd` moves you to another directory.
* `/` refers to the root directory.
* `~` refers to your home directory.
* `.` refers to the current directory.
* `..` refers to the parent directory.
* An absolute path begins at `/`.
* A relative path begins at the current working directory.

These concepts will become especially important when we begin using Git. Git commands usually operate on the project associated with your current working directory, so before running a Git command, you should always know where you are in the file system.
