# What is Git?

In order to understand Git, let's first talk about your computer's files system,
which is most likely the [Unix file system](https://en.wikipedia.org/wiki/Unix_filesystem).
At it's core, the part of the file system that we interact with can be viewed as a graph - more specifically, a directed acyclic graph (DAG). We know about DAGs from CS 2110 and CS 2800, so let's examine the pieces that make up this structure!

### Nodes

There are two main kinds of nodes that we interact with:

1. Files: Documents, programs, images, source code, or any other data stored on your computer.

2. Directories: Folders that can hold files and/or other directories.

One directory is designated as the root directory, written as `/`. Every file and directory in the file system can be reached by starting from this root and traversing across the edges of the file system, which we explain below.

### Edges

A directory contains named references to its contents. Therefore, an edge can connect: a directory to one of its subdirectories or a directory to one of its files.

For example, the path

`/home/project/main.ml`

describes a sequence of traversals:

`/` → `home` →  `project` → `main.ml`

where `main.ml` is a file in the `project` directory, which is a subdictory of the `path` directory, which is a subdirectory of the `home` directory, which is a subdirectory of the root `/` directory. Whew!

Under the hood, Unix file systems also store each file/directory's permissions, owner, size, and other metadata together with the node itself in a data structure called an [`inode`](https://en.wikipedia.org/wiki/Inode). 

What does the "i" in `inode` stand for? No idea! [Not even its co-creator knows](https://lkml.indiana.edu/hypermail/linux/kernel/0207.2/1182.html).
